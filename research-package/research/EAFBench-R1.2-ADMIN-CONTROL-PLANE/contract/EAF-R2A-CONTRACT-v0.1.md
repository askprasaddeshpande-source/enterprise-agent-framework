# EAF-R2A Research Contract v0.1

**Project:** Enterprise Agent Framework (EAF)  
**Benchmark:** EAFBench  
**Foundation:** EAF-RESEARCH-FOUNDATION-R1  
**Status:** DRAFT FOR FREEZE

## Primary research question

Can an authority-aware enterprise-agent architecture improve evidence-grounded and policy-compliant behavior while preserving validated task success?

## Primary proposition

**Agent capability must remain separate from enterprise authority.**

An enterprise action is considered durably valid only when its evidence, policy,
authority, approval, execution, and outcome-validation chain is valid.

## Research truth boundary

- Canonical ground truth is deterministic.
- The model under evaluation has no authority to create benchmark truth.
- Primary validation is deterministic; an LLM judge is prohibited as the primary validator.
- MCP/A2A connectivity does not create enterprise execution authority.
- SAP is a deep reference implementation, not the benchmark ontology.

## Frozen invariants

- **E1.** Capability != authority.
- **E2.** Retrieval != evidence authority.
- **E3.** Every decision-relevant fact must have identifiable provenance.
- **E4.** Current state must not be inferred solely from historical success.
- **E5.** Historically valid evidence remains historically valid even when it no longer determines current state.
- **E6.** Superseded evidence must not control present state unless the mission explicitly requires historical reasoning.
- **E7.** Model confidence must not increase enterprise authority.
- **E8.** User assertion must not silently override authoritative enterprise state.
- **E9.** Unknown remains unknown unless an authorized evidence source resolves it.
- **E10.** Material evidence conflict must not be silently merged.
- **E11.** Equal-authority unresolved contradictions block, re-observe, or escalate according to policy.
- **E12.** A technically available tool does not establish execution permission.
- **E13.** Requester authority and execution authority are evaluated separately.
- **E14.** Recommendation must not be represented as approval.
- **E15.** Approval must not be represented as execution.
- **E16.** Successful tool invocation is not validated enterprise success without required readback.
- **E17.** Consequential actions must be attributable to an authority chain.
- **E18.** Every denied consequential action must have a machine-readable reason.
- **E19.** Every executed consequential action must produce a machine-correlatable execution receipt.
- **E20.** Validation defines durable success.
- **E21.** Policies dominate model preference.
- **E22.** Safety-critical mandatory evidence must not be removed for efficiency.
- **E23.** Benchmark ground truth must not be generated by the evaluated model.
- **E24.** Treatment results must not modify frozen benchmark expectations.

## Experiment boundary

R1 builds the research foundation and benchmark machinery only.

`MODEL_EXPERIMENTS_EXECUTED=0`

The EAF treatment must not be tuned against held-out or falsification outcomes.
